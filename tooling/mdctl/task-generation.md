Run from a clean current-main checkout: `node tooling/mdctl/task-generation.mjs ACTION WORKSPACE MAIN_SHA PR EXECUTOR [VALUE]`. `inspect` reads Git/GitHub and returns a request; save it outside the worktree. `prepare` takes REQUEST_JSON; commit its metadata, then `prove` takes NONCE. Unintegrated executables cannot run through the CLI.

`HISTORY` validates the executor's existing task/context/handoff/leases and retains its request format. `MISSING` is available only when all three task/context/handoff files are absent; an existing file containing JSON null is not absence. The lease registry may be absent or valid without unexpired ACTIVE leases. Partial or malformed history, symlinks, active leases, closed PRs and identity drift block execution. Fresh tasks use `task start`. Existing history bytes remain unchanged. Restarted tasks may reuse older leases; proof must follow task start and precede submission.

For MISSING, the owner must inspect the exact request and personally attest that the prior history is absent in this workspace, no other writers or pending jobs can continue writing within this claim, and the new generation does not retroactively restore the missing history. Bounded searches and generic permission to continue do not establish these facts. The request includes `missingHistoryAcknowledged:true`, `noOtherWritersAttested:true`, `historyNotRetroactivelyRestored:true` and `authority:OWNER_ATTESTED_NO_OTHER_WRITERS`; these become owner testimony only after verified personal consent, not process inspection.

The owner must personally post exactly `APPROVED_TASK_GENERATION:CLAIM_ID:REQUEST_DIGEST:NONCE:MAIN_SHA` on the target PR, after reviewing the concrete request. REQUEST_DIGEST is canonical JSON SHA-256 from `generationDigest`. Agents/apps must not publish this attestation on the owner's behalf. Verification requires the repository owner's numeric identity and login, OWNER association, no app authorship, matching issue/comment URLs, one unedited recent approval, complete bounded pagination and repeated readback. The same marker with `REVOKED_` revokes approval. Missing/null `pin` metadata is equivalent; other comment changes invalidate consent. Both prepare and prove check consent before reserving the lock, again under the lock before proof, and after proof.

Requests expire within 30 minutes and claim expiry; changes to their main, candidate, branch, PR/ref, history, executor or acknowledgements require a new request and consent. Prepare locks the common Git directory, records immutable intent and runs bounded real proofs before projecting LOCAL_PROVEN. PREPARED_REQUIRES_FINAL_PROOF is not acceptance. Prove validates journals, recaptures identity and tests the final commit; receipts bind main, candidate, tree, context and released leases. Source history is neither fabricated nor overwritten, and missing source files remain absent. Generation proof leases do not grant subsequent editing authority. Local ADMISSION/CERTIFY, independent review and remote gates still apply; no preliminary proof becomes final proof.

Journals reside under the worktree Git state at `morro-control/generations/NONCE`. Nonces are single-use. Failure retains evidence/locks for reconciliation: never delete locks or extend requests blindly. Local locking does not fence other environments; provider/Git drift aborts without automatic rollback. CLI errors emit only GENERATION_COMMAND_FAILED. There is no CLI transport injection, bootstrap flag, merge, push, deploy, protection change or acceptance of remote proof.
