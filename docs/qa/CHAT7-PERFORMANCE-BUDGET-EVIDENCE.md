# Chat 7 — Performance Budget Evidence

## Scope

This wave establishes a deterministic performance-budget gate for the public Morro Digital runtime.

The current application build uses TypeScript output rather than a single bundled artifact, so the gate measures the actual emitted runtime surface instead of inventing a bundle metric that the architecture does not have.

## Canonical Web Vitals targets

The performance policy records these user-experience targets:

- LCP: <= 2500 ms
- INP: <= 200 ms
- CLS: <= 0.1

These values are product targets. This PR does not claim that a synthetic CI run is representative field evidence for INP. Final acceptance requires browser/device evidence and, when production analytics exists with consent, field monitoring.

## Enforced asset budgets

The checker fails when any configured budget is exceeded.

Initial limits:

- Assistant startup (CI Chromium): 5,000 ms
- Map startup to ready Home state (CI Chromium): 15,000 ms
- Home linked CSS: 100,000 bytes
- Home linked same-origin JavaScript: 500,000 bytes
- Morro Digital app emitted JavaScript: 3,000,000 bytes
- Runtime package JavaScript (Assistant/Analytics/Core/Geospatial/Navigation/Search): 2,000,000 bytes
- Largest runtime JavaScript file: 350,000 bytes

The baseline visible CSS linked by the current Home is approximately 39 KB, with the largest linked stylesheet approximately 9.4 KB, so the CSS limit has explicit headroom without being unbounded.

## Gate behavior

The browser startup gate measures from navigation start to the visible Assistant input and to the canonical ready Home map state. These synthetic limits are regression guards and are intentionally separate from production Web Vitals/RUM.

The checker:

1. parses the public Home document;
2. resolves same-origin linked CSS and JavaScript;
3. fails if a referenced static asset is missing;
4. walks the emitted Morro Digital JavaScript;
5. walks the browser runtime package outputs;
6. records the ten largest runtime JavaScript files;
7. compares actual bytes against the versioned budget;
8. exits non-zero on regression.

Dynamic `/runtime-config.js` is intentionally excluded from static-file resolution because it is generated by the runtime server.

## CI

`.github/workflows/morro-performance-budget.yml` builds the workspace, runs the checker and uploads the JSON report as evidence.

The workflow is path-scoped to Morro Digital runtime, public assets and the browser runtime packages that can materially change initial application weight. Because the current browser entry imports Analytics, `packages/analytics/src/**` is an explicit trigger and `packages/analytics/dist` is included in emitted runtime-byte accounting. Content cache and Notifications remain excluded from initial-runtime package accounting because current main does not import those packages from the public bootstrap.

The uploaded CI evidence includes both the asset report (`report.json`) and the synthetic startup measurement (`runtime-budget.json`), so the enforced Assistant/map timings are retained with the run.

## Boundary

This wave establishes enforceable asset budgets and canonical Web Vitals targets.

It does not yet claim:

- production RUM;
- final device-matrix LCP/INP/CLS certification;
- network-throttled production-host measurements;
- image-format migration.

Those remain separate Chat 7 / Chat 8 acceptance items.
