## Owner-backed adapters versus placeholders and fallbacks

### Owner-backed and delegated boundaries

Current `createAdminDomainAdapters(...)` composes:

- Businesses through `createBusinessAdminAdapter`;
- CRM through `createCrmAdminAdapter`;
- Affiliates through `createAffiliateAdminAdapter`;
- Products through `createProductsAdminAdapter` over Ticketing;
- Reservations through `createReservationsAdminAdapter` over Ticketing;
- Ticketing through `createTicketingAdminAdapter`;
- Orders, Financial and Payments through `createFinancialAdminAdapter`;
- Content through `createContentAdminAdapter`;
- Destinations through `createDestinationAdminAdapter`.

The Admin API fails closed when an expected adapter is absent. Dashboard module state reports `contract-required` when a domain is not composed.

### Remaining fallback risks

#### Business profile runtime

`apps/morro-digital-platform/tooling/business-api.mjs` defaults to an in-memory profile repository when no repository is injected.

`dev-server.mjs` currently creates `createBusinessApi({ authApi })` without an explicit durable repository.

Conclusion:

- acceptable as a development fallback;
- insufficient evidence for a durable Business administration owner boundary.

#### Business directory

`businessesFromUsers(...)` derives part of the business directory from Auth user memberships.

Conclusion:

- useful projection;
- not a complete Business owner registry.

#### Settings

Current Settings are local preferences.

Conclusion:

- this is safer than inventing privileged configuration authority;
- future server-side settings require redesign first.

#### System

System is a read-only projection.

Conclusion:

- no placeholder write authority exists;
- it should remain read-only until a separate governed operations contract exists.

## Auth and server-authority findings

### Verified strengths

- Capability enforcement is performed server-side in `admin-api.mjs`.
- Critical User actions require `users.manage`, mutation authorization, step-up and audit.
- User session revocation requires `users.sessions.revoke` and step-up.
- Support Mode separates actor from effective user.
- Critical mutations are denied during Support Mode in the audited flows.
- Financial mutations preserve Financial as monetary authority.
- Production financial effects are explicitly code-blocked in the Control Center orchestration path.
- Adapter absence fails closed instead of fabricating owner behavior.

### Remaining authority gaps

1. Business profile durability and the complete Business registry are not proven by the current default runtime composition.
2. CRM and Ticketing need capability-by-capability review for any admin operation not already covered by delegated owner contracts.
3. Settings must not become privileged server configuration until an explicit authority model, mutation policy, audit contract and recovery path exist.
4. Future cross-domain Entity 360 aggregation must remain read-side composition. It must not become a new write authority.
