M58 promotes `Recommendation sandbox` from `GAP` to `PASS`. The frozen V1 sandbox is confirmed as an active onboarding dependency rather than dead code. V2 now constructs an immutable tutorial-only Business candidate, preserves category `+55`, specialty `+30`, business-name `+100` and audience `+15` additive scoring, caps the result at `100`, and renders only at the frozen `>= 50` threshold.

The candidate is evaluated during the real `assistant-query` runtime step after the shared Assistant adapter executes. Evaluation and rendered events are tutorial-only, remain inside onboarding runtime context and are explicitly marked `excludeFromBusinessMetrics: true`. No production Search catalog, recommendation index, analytics endpoint or commercial inventory is created.

The new package subpath `@touristic/business/onboarding-recommendation` is exported explicitly and mapped in the real onboarding HTML import map. The permanent M57 route browser import map was also updated because `business-onboarding-runtime.js` now imports the new subpath; its Chromium contract returned to PASS after that explicit module-boundary update.

`Live Business runtime` remains `PARTIAL`. M58 closes the observable recommendation sandbox contract but does not claim profile sandbox/workspace, partner workspace, analytics breadth or commercial conversion parity. `Profile sandbox/runtime` is now the strongest next Business-owned runtime candidate because frozen V1 call sites connect it to `business-live-runtime.js` and onboarding profile/promotions behavior.

The M54 runtime-isolation rule remains intact. Business onboarding consumes Search, location, Assistant and Navigation through explicit ports/subpaths; the recommendation candidate exists only as Business tutorial state. Protected Business/Auth server consumers retain their existing module graph.

## Dependency rule

No Business implementation milestone may introduce its own credential/session/cookie/CSRF logic. Those contracts belong to `FEATURE-0008` and must be consumed through an Auth-owned boundary.

The onboarding workflow session remains product/workflow state only and is not an authentication authority. It contains no credential, signed cookie, CSRF secret, role token or tenant authorization authority.

Payment/checkout execution remains owned by `FEATURE-0009`; onboarding may expose a future commercial handoff but must not absorb Payments ownership.
