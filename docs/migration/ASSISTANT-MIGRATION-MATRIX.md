## Estado do milestone M17

O M17 fecha a auditoria da origem e da semântica de resolução de lugares da V1. A evidência congelada mostra que `assistant-dialog.js` não usa o GeoJSON bruto como universo principal: ele importa `js/map/locations/locations.js`, achata as categorias em `allPlaces`, exige nome/coordenadas válidos e aplica o filtro de 12 km ao redor de Morro de São Paulo. `dadosGeoJSON` serve principalmente como fallback de metadados/detalhes. O `map-commander.js` reforça o mesmo contrato ao cair de `KNOWN_PLACES` para `window.locations`.

O runtime V2 agora usa `assistant-v1-place-resolver.ts`, que reproduz a precedência V1 de `findPlace`: nome exato → alias exato → inclusão por nome/alias → Dice fuzzy, com threshold congelado em `0.55`. Há regressões para cada classe de match, typo fuzzy e retorno nulo para texto desconhecido.

A integração Navigation permanece `PARTIAL` porque o catálogo M16 ainda contém 34 destinos, enquanto a V1 expõe o conjunto curado mais amplo de `locations.js`. O próximo checkpoint deve migrar/gerar esse catálogo completo preservando categorias, aliases, coordenadas e o filtro V1 antes de promover resolução de place name e Navigation para `PASS`.

Auditoria formal adicional: `docs/qa/ASSISTANT-V1-PLACE-RESOLUTION-AUDIT.md`.

A FEATURE-0004 / MIG-0006 **não** está equivalente neste checkpoint. Permanecem gaps em handlers de domínio, provider LLM same-origin, voz, catálogo integral de lugares e UI completa do assistente.

Para promover MIG-0006 a `equivalent`, todos os itens acima precisam estar em PASS e o Quality Gate do head final deve estar integralmente verde.
